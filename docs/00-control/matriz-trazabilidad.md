# Matriz de trazabilidad

## 1. Alcance de esta versión

Esta matriz cubre las decisiones `DEC-001` a `DEC-069`. B0, `HU-020` ([PR #70](https://github.com/bcaceres19/barberia/pull/70)) y `HU-021` ([PR #72](https://github.com/bcaceres19/barberia/pull/72)) están integradas en `main` con contrato, migraciones, Go, Vue y pruebas reales. `HU-022` tiene PR real abierto ([#79](https://github.com/bcaceres19/barberia/pull/79), `Closes #75`, verificado localmente contra PostgreSQL 14 real y E2E real contra Chromium) pero **aún no está integrado en `main`**; `HU-023`/`HU-024` tienen sus decisiones resueltas (`DEC-068`, `DEC-069`) e issue real (`#76`, `#77`), bloqueadas solo por el orden de integración. El resto de B1 y B2–B6 sigue la secuencia de [plan-bloques.md](../10-backlog/plan-bloques.md). `database/modelo-fisico-referencia.sql` continúa siendo insumo de diseño, no una migración aplicada.

Una historia redactada tampoco es una historia implementada, y un PR abierto tampoco es un PR integrado: `HU-001`–`HU-012`, `HU-020` y `HU-021` tienen entregas integradas en `main`; `HU-022` tiene PR real verificado localmente pero pendiente de revisión/CI/merge; `HU-023`–`HU-024` todavía no tienen implementación, aunque ya no dependen de ninguna decisión de producto pendiente. El marcador `Pendiente` representa una brecha real; no se crean identificadores ficticios para aparentar cobertura.

La cadena exigida es:

`Función → Decisión → Regla → Historia → Criterio → API/datos → Prueba → Métrica`
